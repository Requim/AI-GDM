# AI-GDM MVP 已知限制 v1

## 业务边界

- 本系统是面试评估和辅助决策 MVP，不是国家正式地质灾害预警发布平台。
- 当前真实风险主链只接入 NASA LHASA 滑坡数据。接口具备多灾种扩展机制，但不得把滑坡结果改名为泥石流、洪水或其他灾种结论。
- 风险图层是模型输出，不是现场传感器、遥感解译、地质调查或群众报灾的替代品。
- 疏散路线与设施是候选方案，不代表交管部门确认道路开放、车辆可用、设施有容量或现场安全。
- 生还评估只用于公开历史案例和合成匿名场景回放，禁止用于真实失联人员的自动决策。

## 数据与模型

- 公共互联网接口可能限流、变更合同或中断。过期数据不得继续标成当前；损失模块仅允许在过期后 72 小时内生成明确标记、很低置信度的研究参考区间，其他实时用途保持不可用。
- Open-Meteo 是数值天气模型输出，不是本地雨量站实测。
- 暴露数据质量取决于 WorldPop、OpenStreetMap 和行政边界公开数据的覆盖度与时效。
- 默认 Open-Meteo 只监控成都、昆明两个可配置点，不代表全国气象覆盖；geoBoundaries 当前只使用中国 ADM0 国家级边界。
- 仓库不包含可作为生产结论的资产单价、脆弱性参数或地区校准值；未导入真实已批准基线时，只能在有真实道路暴露和可审计案例来源时生成 `reference_only` 研究参考区间。
- AI 文本可能不完整或表达不当，只能解释确定性结果；用户应以确定性卡片、来源和限制为准。
- 当前没有经核验的实时灾害事件目录；页面只能把事件源状态显示为未知，不能据此宣称“当前没有灾害”。

## 部署与运维

- 离线包只消除镜像仓库依赖，实时 Earthdata、Open-Meteo、WorldPop、Overpass、geoBoundaries、高德、搜索和 LLM 仍需要互联网。
- `v0.1.1` 为单节点 Docker Compose 部署，没有高可用、自动故障转移、跨节点调度或自动备份。
- 默认直接提供 HTTP `8080`，不含 TLS 终止。长期公网运行必须增加可信反向代理、证书、网络访问控制和密钥轮换。
- 管理操作使用共享 Bearer Token，不含多用户、角色权限、SSO 或细粒度审计主体。
- PostgreSQL、Redis 和 LHASA 数据通过命名卷持久化，但备份、恢复演练、容量告警和灾备由部署方负责。
- 完整空缓存一键部署验收在 Linux AMD64 腾讯 Ubuntu 完成；Windows Docker Desktop 脚本通过语法和合同测试，但未在本阶段完成真实 Windows 空缓存端到端验收。

## 评估时必须核对

- 页面是否显示数据更新时间、有效期、来源和降级状态。
- 供应商失败后是否保留明确标记的最后成功数据，且到期后停止标为当前。
- 风险、路线、损失和生还卡片是否保持确定性，AI 文字是否只在独立区域展示。
- 损失评估是否绑定真实已批准基线；若没有，只能是明确标记的 `reference_only` 道路研究参考，输入不足时仍必须保持 `insufficient_data`。
- 服务器私有配置、日志、Git 历史和 Release 附件中是否没有 API Key、令牌、Cookie 或真实人员数据。
