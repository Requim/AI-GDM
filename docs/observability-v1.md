# AI-GDM 运行观测与降级边界

## 目标

P9.2 为值守控制台提供进程内业务观测、受保护指标和写操作审计。观测只描述当前服务进程从启动至今实际看到的结果，不替代供应商 SLA、长期监控平台或人工复核。

## 业务级观测

- 固定组件只有 `lhasa`、`weather`、`amap`、`bocha` 和 `llm`，运行时不能创建动态标签。
- 结果只允许 `success`、`degraded` 和 `failure`。最后成功回退属于 `degraded`，不能计为实时供应商成功。
- HTTP 200、缓存命中、配置了 API 密钥或服务进程可启动，均不等于供应商业务结果可用。
- 指标在进程重启后归零；最后成功时间不等于当前仍可用，数据是否过期仍以权威来源 `validTo` 判断。

## 指标接口

- `GET /metrics` 使用与写操作相同的管理员 Bearer 令牌保护，未配置或未授权时 fail-closed。
- 输出 Prometheus 0.0.4 文本，标签只包含固定组件和固定结果，不包含 URL、请求 ID、快照 ID、模型名、用户输入、原始错误或供应商请求 ID。
- 响应禁止缓存。指标只用于本次面试服务的进程级排障，不声明长期可用率。

## 写操作审计

- 受保护写请求记录固定动作、HTTP 方法、规范 Request-ID、共享角色类型、状态码、结果和耗时。
- 审计不记录查询串、请求体、Authorization、Cookie、原始 IP、人员信息或原始错误文本。
- 当前使用共享管理员令牌，日志只能证明共享角色通过或被拒绝，不能把操作归属到具体人员。
- 结构化标准输出不是防篡改审计仓库，也不保证跨进程长期留存；正式生产需接入集中日志、保留策略和个人身份体系。

## 控制台状态

- `waiting`：功能已启用，但当前进程尚未形成业务级观测，或尚无持久化成功数据。
- `degraded`：最近业务调用失败或使用最后成功回退，但仍有未过期的持久化结果可展示。
- `stale`：权威数据已经超过有效期。该状态优先于最近调用结果，不能被新页面渲染或缓存命中刷新。
- `unknown`：缺少能支持结论的数据源。当前未接入经核验的实时事件目录，因此只能显示“无法判断当前是否存在实时事件”，不得表述为没有灾害。
- `unavailable`：必要依赖、持久化结果或响应契约不可用，系统不会生成模拟数据替代。

## 降级原则

- NASA LHASA 或 Open-Meteo 刷新失败时，只能使用仍在有效期内的最后成功数据并标记降级；过期后停止作为当前结果使用。
- 高德、博查或 LLM 失败不得修改确定性的风险等级、路线安全判断、损失金额或生还评分。
- 外部供应商失败不应使基础 HTTP 进程失去存活；依赖就绪、业务降级和数据过期必须分别呈现。
