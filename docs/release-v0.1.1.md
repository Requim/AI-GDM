# AI-GDM v0.1.1 发布说明

发布日期：2026-09-01

## 版本定位

`v0.1.1` 是面向 `v0.1.0` 的向前升级维护版本，集中交付 API 路由、评估联动、全国风险图层、局部热点损失参考和 AI 解读稳定性修复。它包含单向数据库迁移，不承诺升级后可只替换旧镜像完成回滚。确定性风险、路线、损失和生还评分仍由规则代码生成，大模型只负责解释。

## 主要更新

- 修复应用 API 嵌套路由分发，恢复搜索候选设施和疏散路线接口。
- 损失评估自动绑定当前有效风险快照，并把指标用途、输入来源和限制改为更通俗的页面说明。
- 放宽空间分析中合理的地理面积误差，同时继续拒绝越界、损坏或不一致的数据。
- 修复博查可信域检索；超过 `72h` 的结果继续被排除，不冒充实时证据。
- 新增局部高风险热点的道路损失研究参考估算，并允许最近 `72h` 最后成功投影以 `reference_only / very_low` 有界降级。
- 使用中国 ADM0 边界裁剪风险区域，并以亚像元统计保留国界附近真实覆盖，浏览器仍按风险优先级限制显示载荷。
- 按结构化输出尝试次数分配 AI 解读超时预算，避免正常慢响应被固定 `10s` 提前降级；供应商失败时仍保留确定性结果。

## 数据库升级

本版本新增迁移 `010_loss_reference_status.sql` 和 `011_hazard_snapshot_coverage.sql`。升级前必须备份 PostgreSQL 和私有运行配置；使用发布包部署脚本时，应用会在启动阶段按顺序执行尚未应用的迁移。迁移后生成的新 Authority 数据不能保证由 `v0.1.0` 读取，不得只把应用镜像切回旧版本。

如必须回滚，应先停止应用并阻止新写入，再把 PostgreSQL 恢复到升级前备份，同时恢复原发布包和应用镜像，最后按原运行配置重新启动并验收。没有数据库备份时应继续运行 `v0.1.1` 并修复问题，而不是让旧二进制连接已升级数据库。

## 发布制品

- `ai-gdm-v0.1.1-linux-amd64.tar.gz`
- `ai-gdm-v0.1.1-linux-amd64.tar.gz.sha256`
- `ai-gdm-v0.1.1-git-log.txt`
- `ai-gdm-v0.1.1-git-log.txt.sha256`

发布包内 `manifest.json` 绑定最终 `sourceCommit`、Git tree、规范源码 SHA-256、三个离线镜像及全部 payload 摘要。Git 日志附件从发布提交动态导出，不进入仓库。

## 升级方式

1. 下载发布归档及同名 `.sha256`，执行严格校验后解压。
2. 继续使用原来的绝对 `AI_GDM_RUNTIME_ENV_FILE`、`AI_GDM_PROJECT_NAME` 和命名卷。
3. 在新包根目录执行 `deploy/deploy.sh`；不要复制旧包的 `release-images.env` 覆盖新版本。
4. 验证 `/healthz`、`/readyz`、控制台首页、数据库迁移和供应商状态。

## 验证口径

- 全仓 Go 测试、`go vet` 和完整构建。
- 发布包精确文件清单、Linux/Windows 二进制、三个原始镜像、manifest、内外层 SHA-256 和只读 releasecheck。
- 空镜像缓存中的一键部署、重复部署、保留卷停启以及 PostgreSQL、Redis、LHASA 持久化。
- 系统、风险地图、疏散和评估浏览器回归无失败或跳过。

## 已知限制

完整限制见 `docs/limitations-v1.md`。本版本仍是单节点 HTTP MVP；实时业务依赖外部互联网和供应商；损失金额仅是明确标记的数据约束参考；历史生还回放不得用于真实人员自动决策；AI 文本不得替代确定性卡片、来源和限制。
