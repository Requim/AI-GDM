# AI-GDM 风险研判规则 v1

## 定位

本规则生成面试评估用途的确定性辅助研判结果，不是 NASA 风险等级、中国官方预警等级或现场处置命令。规则版本固定为 `ai-gdm-risk-rules-v1`；任何会改变等级、时效或置信度语义的修改都必须提升版本。

## 输入边界

- 主输入为同一灾种的完整 `Snapshot` 和其全部 `RiskZone`。
- 引擎构造时必须通过 `ModelCapability` 固定绑定灾种、模型名和数据集；快照三项均与能力声明一致后才能参与评估。
- 气象上下文必须由调用方先完成空间选择，并记录选择方法；P3.1 不自行把任意监测点绑定到风险区。
- `landslide` 和 `debris_flow` 只接受各自专用的概率快照。当前 Earthdata `LHASA_Hazard_Today` 只进入滑坡链路，不得改名生成泥石流结论。
- 所有评估时间由调用方显式传入 UTC，领域引擎不读取系统时钟。

## 等级规则

风险区等级沿用快照中版本化阈值，并校验最小值、均值和最大值均落在同一档：

| 等级 | AI-GDM v1 概率区间 |
| --- | --- |
| 低 | `[0, 0.1]` |
| 中 | `(0.1, 0.5]` |
| 高 | `(0.5, 0.9]` |
| 极高 | `(0.9, 1]` |

整体等级取全部风险区的最高等级。完整快照没有生成高于 `0.1` 的风险区时，整体等级为低，但必须保留“低风险不等于无风险”的限制说明。引擎不会使用区域均值重新覆盖 GDAL 已生成的区域等级，只负责验证一致性和确定性聚合。

## 数据状态

- `current`：主模型处于有效期，且没有最后成功回退标记。
- `fallback`：主模型仍在有效期，但 `SnapshotStale`、`Source.Stale` 和 `fallback_last_success` 一致表明使用最后成功结果。
- `expired`：评估时刻晚于快照或来源的 `ValidTo`。恰好等于 `ValidTo` 仍有效，晚一纳秒即过期。

过期结果状态为 `insufficient_data`，不包含可操作等级，不允许降为低风险。

## 数据质量置信度

置信度只描述主模型输入的完整性、时效和可追溯性，不是灾害发生概率：

- `high`：数据当前有效，具有可信观测或发布时间、来源修订、内容校验和，且没有质量标志。
- `medium`：数据当前有效，但可信模型时间、修订、校验和或质量条件至少一项不足。Earthdata 当前未提供精确模型运行时间，因此最高为 `medium`。
- `low`：使用有效期内最后成功结果。
- `unavailable`：主模型已过期，未生成等级。

## 触发因素

- `model_risk_zones` 是唯一决定等级的因素。
- 历史总降水、预报总降水和五层土壤湿度均标记为 `context_only`、`affectsLevel=false`。
- 总降水只汇总 `PrecipitationMM`，不会重复相加 `RainMM` 和 `ShowersMM`。
- 五层体积含水率按原值和层深输出，不求简单平均，不套用统一湿润阈值，也不替代 LHASA 使用的土壤湿度输入。
- 气象上下文缺失、回退或过期不会改变主模型等级和主模型数据质量置信度；其独立状态会进入结果和限制说明。多上下文中只有部分过期时标记为 `partial`，全部过期才标记为 `unavailable`。

## 确定性与审计

输入引用、最高等级风险区和气象上下文均排序、去重。评估标识由不含自身标识的完整规范化结果生成；相同输入产生相同输出，数据状态或上下文变化会产生不同标识。引擎不修改传入切片，也不访问数据库、缓存、网络、GDAL 或系统时间。

## 科学限制与参考

LHASA v2 已在模型中使用当前降雨、前期降雨和土壤湿度等信息，因此 Open-Meteo 只作为独立上下文，避免同类证据重复计分。现有阈值是 AI-GDM 演示规则，不宣称为 NASA 推荐业务阈值。
