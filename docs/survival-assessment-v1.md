# 生还可能性辅助评估 v1

## 计算边界

评估只读取服务端案例目录中与公开历史案例唯一绑定、`Synthetic=true` 的合成匿名搜救场景。浏览器只能按 `caseID` 发起回放，不能提交或覆盖场景字段。规则从 50 分开始，根据失联时长、输入完整度、可呼吸空间、饮水、危险源稳定性、重伤信号和通信状态进行固定加减分，再把 0 到 100 分映射为宽概率区间和搜救优先级。

规则版本固定为 `ai-gdm-survival-rules-v1`。相同场景摘要和模型版本产生同一确定性结果标识；输出绑定 `caseId`、`scenarioId`、`scenarioDigest`、模型版本和历史回放用途声明，并包含评分、概率带、优先级、主要因素及固定的 `humanReviewStatus=required`。页面必须同时读取 `/api/v1/survival/model-card`，只有模型卡版本与评估结果完全一致时才能将结果标记为可解释。

## 回放接口

- `GET /api/v1/survival/cases`：列出公开历史案例及其合成匿名场景标识。
- `GET /api/v1/survival/cases/{caseID}`：返回案例、合成匿名场景、场景摘要和用途声明。
- `POST /api/v1/survival/replays/cases/{caseID}/assessment`：执行案例级确定性回放，请求体必须为空。
- `GET /api/v1/survival/model-card`：返回与结果 `modelVersion` 绑定的机器可读模型卡。

## 科学限制

- 概率是辅助研判的宽区间，不是经临床或个体数据校准的生还概率。
- 历史案例存在报告偏差，不能从事件级数据外推到具体人员。
- 规则不读取或推断姓名、伤情诊断、医疗记录等敏感个人信息。
- 现场危险源、伤情、通信和天气变化必须由有资质的搜救人员重新确认。
- 所有结果必须明确标记为“公开历史案例 + 合成匿名场景回放”，不得使用“当前可用”“实时个案评估”等措辞。

任何评估结果都不能作为自动停止搜救、医疗分诊或替代指挥员判断的依据。
