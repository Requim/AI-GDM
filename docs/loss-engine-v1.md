# 可解释损失引擎 v1

P5.2 的损失引擎只使用已保存的风险快照、风险区空间分析、版本化成本基线、脆弱性基线和资产暴露记录。它不调用大模型，也不把缺失数据替换为零或演示数值。

## 计算公式

每个资产类别分别计算三种条件情景：

```text
损失金额（分） = 暴露量 / 覆盖率 × 单位重置成本（分） × 影响比例 × 损伤率
```

低、中、高情景分别使用成本和脆弱性基线中的对应字段，按风险区级别选择对应脆弱性并最终按资产类别求和。金额使用整数和有理数完成确定性计算与舍入，避免 `float64` 丢失人民币分。公式版本固定为 `ai-gdm-loss-formula-v2`，写入评估结果，便于审计和回放。

## 输入和拒绝条件

- 风险快照必须与请求的快照标识和灾种一致，状态为 `available` 且仍在有效期内；`stale`、过期或内容错绑均 fail-closed。
- 服务端通过单事务无几何投影读取全部风险区、空间分析与当前暴露投影，客户端不能提交暴露量。人口、道路和设施 feature 按全局身份去重，并绑定一个或多个风险区。
- 每种计价资产必须找到同区域成本和对应风险等级脆弱性参数；找不到时再尝试国家级 `CN` 已批准基线，仍缺失则返回 `insufficient_data`。
- 成本、脆弱性、空间分析或风险快照读取失败时保留 `errors.Is` 错误链，不生成部分金额。
- `partial`、`unavailable`、超量或来源损坏的空间投影不生成可用金额。置信度表示输入完整性，不等同于灾害发生概率。

## 输出限制

结果包含十进制字符串形式的低/中/高人民币分值、去重影响面积、人口上下文、道路和设施直接物理损害、输入引用、基线层级、公式版本、置信度和限制说明。它不是校准后的期望损失，也不是财政核损、保险理赔或官方灾情认定；大模型只能在后续 AI 编排阶段解释这些不可变数值。

## 远端验证

在指定腾讯 Ubuntu 验证服务器执行：

```sh
sudo sh scripts/validate-loss.sh
```

验证包含 Go 模块校验、损失领域和应用层竞态测试、`go vet ./...` 与 `go build ./...`。
