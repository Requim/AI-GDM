# 可解释损失引擎 v1

P5.2 的损失引擎只使用已保存的风险快照、风险区空间分析、版本化成本基线、脆弱性基线和资产暴露记录。它不调用大模型，也不把缺失数据替换为零或演示数值。

## 计算公式

每个资产类别分别计算三种条件情景：

```text
损失金额（分） = 暴露量 / 覆盖率 × 单位重置成本（分） × 影响比例 × 损伤率
```

低、中、高情景分别使用成本和脆弱性基线中的对应字段，最终按资产类别求和。金额在计算过程中以人民币分保存并在最后取整，避免浮点结果直接作为展示金额。公式版本固定为 `ai-gdm-loss-formula-v1`，写入评估结果，便于审计和回放。

## 输入和拒绝条件

- 风险快照必须与请求的快照标识和灾种一致，且状态为 `available` 或 `stale`。
- 风险区必须属于同一快照，资产暴露必须引用已知风险区并通过来源、年份、数量和覆盖率校验。
- 每种资产必须找到同区域脆弱性参数；找不到时再尝试校准区域 `CN`，仍缺失则返回 `insufficient_data`。
- 成本、脆弱性、空间分析或风险快照读取失败时保留 `errors.Is` 错误链，不生成部分金额。
- 过期快照和部分空间分析会降低置信度，并在输入依据中保留过期标记。置信度表示输入完整性，不等同于灾害发生概率。

## 输出限制

结果包含低/中/高人民币分值、影响面积、上下文暴露量、输入引用、资产类别、公式版本、置信度和限制说明。它是辅助研判，不是财政核损、保险理赔或官方灾情认定；大模型只能在后续 AI 编排阶段解释这些不可变数值。

## 远端验证

在指定腾讯 Ubuntu 验证服务器执行：

```sh
sudo sh scripts/validate-loss.sh
```

验证包含 Go 模块校验、损失领域和应用层竞态测试、`go vet ./...` 与 `go build ./...`。
