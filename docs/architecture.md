# AI-GDM 后端架构

## 系统定位

AI-GDM 是面试评估用途的地质灾害辅助研判系统。首版处理降雨触发滑坡风险；所有结果必须展示数据来源、时间、模型版本和限制，不得描述为国家官方预警。

LHASA 是近实时模型输出，不是现场观测，也不能覆盖所有泥石流类型。Open-Meteo 是数值天气模型输出。高德返回的是候选路线，不代表交管部门确认道路开放。公开数据不足时，系统必须返回数据不足或过期状态，而不是生成模拟实时数据。

## 六边形架构

依赖方向固定为：`adapters -> application -> domain`。`cmd/server` 是唯一组合根，负责把具体适配器注入应用用例。

### 领域层

领域层保存灾害快照、风险区、数据溯源、暴露量、路线、损失情景和历史事件等模型。该层不导入 HTTP、SQL、Redis、GDAL、高德、博查或 Qwen 包。

### 应用层

应用层按用例拆分实时采集、风险分析、疏散规划、损失评估、历史回放和报告生成。应用服务仅通过小粒度端口访问外部能力。

### 适配器层

每个供应商拥有独立适配器和契约测试。供应商 DTO 在适配器内转换成领域对象，不允许泄漏到应用层。

## SOLID 约束

- 单一职责：采集、解析、分析、持久化、展示和报告分别维护。
- 开闭原则：新增灾种通过 Provider、Analyzer 和注册表接入，不修改既有灾种用例。
- 里氏替换：同类适配器必须通过统一契约测试，错误和过期语义一致。
- 接口隔离：读取风险、读取天气、搜索设施、规划路线和生成说明使用不同接口。
- 依赖倒置：业务用例依赖 ports；所有具体客户端只在组合根创建。

## 数据分类与溯源

数据分类固定为 `observation`、`nowcast`、`forecast`、`baseline` 和 `historical`。每条外部数据至少记录供应商、数据集、版本、来源地址、观测时间、抓取时间、坐标系、校验和、许可和质量标志。

人口、道路、资产价格和历史事件不得标记为实时数据。损失金额缺少经审核的成本或脆弱性基线时，返回 `insufficient_data`，不得用零值或模型猜测替代。

## AI 边界

Qwen 仅接收去标识化、结构化的分析结果和公开证据。输出必须经过结构校验；模型不可参与核心数值运算。搜索或大模型不可用时，确定性结果仍可返回，并标记对应说明不可用。

## 隐私边界

公共仓库和演示环境不保存姓名、联系方式、证件号、精确行踪或医疗信息。首版只展示有来源的事件级历史回放；没有合法公开的个体生还训练数据时，不宣称输出经验证的个人生还概率。
